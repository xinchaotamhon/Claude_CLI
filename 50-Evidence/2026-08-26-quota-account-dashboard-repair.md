# Quota, pending-account, terminal and root cleanup evidence

## Reproduction and root causes

- The old Codex adapter parsed a local auth payload and called an undocumented
  HTTP endpoint directly. It had no first-party protocol boundary.
- `codex_free_2` contained project-local login state and its label marker, but
  no account-profile route; dashboard discovery therefore omitted it.
- The terminal wrapper used `cmd /k`, leaving its console open.
- Google onboarding and the frontend were hard-coded to three slots. Errors
  closed the action window before the owner could read them.
- Four owner-facing BAT files remained at project root.

## Implemented controls

- Codex usage now spawns the exact pinned project-local `codex.exe app-server
  --stdio`, sets the exact account home, performs the JSONL handshake and calls
  `account/rateLimits/read`.
- Primary, secondary, individual monthly limit and reset-credit count remain
  distinct. Labels come only from `windowDurationMins`; reset credits are never
  redeemed by the dashboard.
- Official `resetsAt` timestamps are normalized, and the Codex child receives
  only the exact project-local account home after inherited OpenAI/Codex/
  ChatGPT/Azure OpenAI credential variables are removed.
- Ready-account usage refreshes when stale at startup and every five minutes.
- Project-local Codex homes with login plus label marker but no route appear as
  incomplete and can resume the exact local import.
- Safe email-style labels containing `+` and `@` survive resume as a separate
  quoted argument; command metacharacters remain rejected.
- Terminal spawn uses `/c`; successful account actions close, while failures
  pause with their diagnostic visible.
- Google slots are allocated dynamically from 1 through 50 with callback port
  `51120 + slot` and rediscovery of incomplete state.
- Only `DASHBOARD.bat` remains at root. Technical launchers moved to `tools/`.

## Live bounded observations

- Official app-server read for `codex_free_1`: plan `free`; primary window
  `43200` minutes; `usedPercent=1`; no secondary or individual limit; zero
  reset credits. Expected and observed dashboard value: monthly remaining 99%.
  No weekly value was fabricated.

  `codex_free_2` incomplete. The exact resume path then recovered the provider
  already persisted by CCR, created Terra/Luna routes and removed pending state

- Final account-profile enumeration contains four routes: Terra/Luna for each
  of `codex_free_1` and `codex_free_2`. Root BAT enumeration returned only
  `DASHBOARD.bat`.
- After inherited credential variables were scrubbed, a second live official
  read for `codex_free_2` still returned `free`, monthly remaining 100% and
  reset timestamp `2026-09-25T07:52:22Z`.
- No Google OAuth was initiated during implementation or verification.

## Source decision

- Adopted the official OpenAI app-server protocol and schemas generated by the
  exact pinned local binary.
- `Tooblippe/codex-usage` is reference-only; no second runtime was vendored.
- `crsxmilitaru/ag-usage` is reference-only because it requires an external
  Antigravity IDE process.
- `devtint/AntigravityQuotaManager` was rejected because auto-wakeup can consume
  quota and expands external IDE coupling.
